# PR #7836 — program-runtime: create new `memory` module

- **Date:** 2025-09-03

## Summary

Creates a new `memory` module in `program-runtime` containing memory
translation utilities. Moves `address_is_aligned`, `translate_inner!`,
`translate_type_inner!`, and `translate_slice_inner!` from `syscalls/src/lib.rs`
to `program-runtime/src/memory.rs`. Introduces a `MemoryTranslationError` type
to replace syscall-specific error variants in the macros. Also extracts
CPI-specific `translate_type_mut` and `translate_slice_mut` from
`syscalls/src/cpi.rs` into public functions in the new module.

### Category C: Behavioral Changes

**Error type change in macros:**

The `translate_type_inner!` and `translate_slice_inner!` macros previously
emitted `SyscallError::UnalignedPointer` and `SyscallError::InvalidLength`.
After the move to program-runtime, they emit
`MemoryTranslationError::UnalignedPointer` and
`MemoryTranslationError::InvalidLength`.

Both are boxed via `.into()` to `Box<dyn std::error::Error>`, so the return
type is the same. However, the **concrete type inside the box** changed:

| Error Path | Before | After |
|-----------|--------|-------|
| Unaligned pointer | `Box<SyscallError::UnalignedPointer>` | `Box<MemoryTranslationError::UnalignedPointer>` |
| Invalid length | `Box<SyscallError::InvalidLength>` | `Box<MemoryTranslationError::InvalidLength>` |

**Impact analysis:**
- Error messages are identical ("Unaligned pointer", "Invalid length" / "InvalidLength").
- Code that downcasts `Box<dyn Error>` to `SyscallError` would fail to
  match. However, the syscall error path boxes errors as trait objects and
  propagates them through the SBPF VM — no downcast to `SyscallError`
  occurs in the production error handling chain.
- A `#[from] MemoryTranslationError` variant was added to `SyscallError`
  to allow conversion, but this wraps as
  `SyscallError::MemoryTranslation(err)`, not the original flat variants.
  A later PR in the series replaces this with a manual `From` impl that
  maps back to the original flat variants (`SyscallError::UnalignedPointer`,
  `SyscallError::InvalidLength`).

**Assessment:** SAFE — the error change is contained within trait object
propagation. No production code downcasts these errors. The error messages
are identical. The `#[from]` variant was later cleaned up.
