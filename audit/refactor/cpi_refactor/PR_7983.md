# PR #7983 — program-runtime: port over translate account functions

- **Commit:** `1c06bd3601bd62ada7a31bd114010b1a953f8278`
- **Date:** 2025-09-10
- **Files changed:** 3 (199 insertions, 198 deletions)

## Summary

Moves `translate_account_infos()` and `translate_and_update_accounts()`
from `syscalls/src/cpi.rs` to `program-runtime/src/cpi.rs`. Also adds a
`type Error` alias and a local `consume_compute_meter` helper in the
program-runtime cpi module.

## File Summary

### Category A: Pure Moves

| Item | Notes |
|------|-------|
| `translate_account_infos()` | Visibility: private -> `pub`. One error variant change (see Cat C). |
| `translate_and_update_accounts()` | Visibility: private -> `pub`. One error variant change (see Cat C). |

### Category B: Structural Changes

- **`type Error = Box<dyn std::error::Error>` added** to
  `program-runtime/src/cpi.rs`. All existing functions in the module
  updated from explicit `Box<dyn std::error::Error>` to `Error`. Pure
  alias introduction, no behavioral change.
- **`consume_compute_meter` re-introduced** as a local helper in
  `program-runtime/src/cpi.rs` — identical one-line pass-through to
  `invoke_context.consume_checked(amount)`. Needed because
  `translate_and_update_accounts` uses it and the original in syscalls
  is not accessible cross-crate.
- **Import shuffling:** `IndexOfAccount` moved from production to test
  imports in `syscalls/src/lib.rs`. `SerializedAccountMetadata` removed
  from `syscalls/src/cpi.rs` imports (now internal to program-runtime).

### Category C: Behavioral Changes

Two error variant changes, same pattern as prior PRs:

| Function | Old | New |
|----------|-----|-----|
| `translate_account_infos` | `SyscallError::InvalidPointer` | `CpiError::InvalidPointer` |
| `translate_and_update_accounts` | `SyscallError::InvalidLength` | `CpiError::InvalidLength` |

Both boxed as `Box<dyn Error>`. Error messages identical. No production
downcast.

**Assessment:** SAFE.

### Category D: Test-Only Changes

- `syscalls/src/cpi.rs` tests: added `IndexOfAccount` import (previously
  available via parent scope, now needed explicitly).
