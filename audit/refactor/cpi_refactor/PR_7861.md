## Summary

Creates a new `cpi` module in `program-runtime` and moves CPI types,
validation functions, and `CallerAccount` from `syscalls/src/cpi.rs`.
Introduces a `CpiError` type to replace `SyscallError` usage in the moved
code. Also replaces the `#[from] MemoryTranslationError` wrapper variant
from PR #7836 with manual `From` impls that map error variants one-to-one.

### Category B: Structural Changes

- **`consume_compute_meter` inlined:** `CallerAccount::from_account_info`
  and `from_sol_account_info` called `consume_compute_meter(invoke_context, amount)`.
  The new code calls `invoke_context.consume_checked(amount)` directly.
  `consume_compute_meter` was a one-line pass-through
  (`syscalls/src/lib.rs:274-277`), so this is an inlining with zero
  behavioral difference.

- **Visibility escalation:** All moved structs and their fields changed from
  private to `pub`. Required for cross-crate access from `syscalls`.
  The `#[repr(C)]` layout is preserved on all structs.

- **`translate_slice_mut_for_cpi` removed from `syscalls/src/cpi.rs`
  imports:** Now only `translate_slice` (immutable) is imported from the
  memory module. The mutable CPI translations happen inside
  `program-runtime/src/cpi.rs` via `use crate::memory::...` in the
  method bodies.

### Category C: Behavioral Changes

**Error type consolidation (same pattern as #7836):**

New `CpiError` enum introduced in `program-runtime/src/cpi.rs` with
variants mirroring a subset of `SyscallError`. Moved functions now emit
`CpiError` variants boxed as `Box<dyn Error>` instead of `SyscallError`.

| Old | New |
|-----|-----|
| `SyscallError::InvalidPointer` | `CpiError::InvalidPointer` |
| `SyscallError::MaxInstructionAccountsExceeded{..}` | `CpiError::MaxInstructionAccountsExceeded{..}` |
| `SyscallError::MaxInstructionDataLenExceeded{..}` | `CpiError::MaxInstructionDataLenExceeded{..}` |
| `SyscallError::MaxInstructionAccountInfosExceeded{..}` | `CpiError::MaxInstructionAccountInfosExceeded{..}` |
| `SyscallError::ProgramNotSupported(..)` | `CpiError::ProgramNotSupported(..)` |

Error messages are identical. The concrete type inside `Box<dyn Error>`
differs but no production code downcasts these errors.

**`From` impl cleanup (fixes #7836 note):**

This PR replaces the `#[error(transparent)] MemoryTranslation(#[from]
MemoryTranslationError)` variant added in #7836 with a manual
`From<MemoryTranslationError> for SyscallError` that maps directly to the
original flat variants (`UnalignedPointer`, `InvalidLength`). Also adds
`From<CpiError> for SyscallError` with the same one-to-one mapping. This
means any code that converts these errors to `SyscallError` preserves the
original variant identity.

**Assessment:** SAFE — error type change is contained within trait object
propagation. The manual `From` impls ensure that when conversion to
`SyscallError` is needed, the original variants are preserved.
