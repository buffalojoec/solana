## Summary

Extracts the `syscalls` module from `programs/bpf_loader/src/syscalls/` into
a new top-level crate `syscalls/` (published as `agave-syscalls`). All
consumers are updated to import from the new crate path.

### Test-only changes — Category D

- `mock_create_vm!` macro **removed** from `programs/bpf_loader/src/lib.rs`.
  This was only used in tests and is replaced by direct `SyscallContext`
  setup.
- `cpi.rs` tests: `mock_create_vm!` call replaced with explicit
  `invoke_context.set_syscall_context(...)` call.
- New `setup_alloc_test!` macro in `syscalls/src/lib.rs` tests — replaces
  `mock_create_vm!` for the `SyscallAllocFree` tests. Sets up a
  `SyscallContext` with a `BpfAllocator` and `MemoryMapping` directly,
  without creating a full VM.

  **`setup_alloc_test!` vs old `mock_create_vm!` comparison:**

  The old path went through `mock_create_vm!` -> `create_vm!` -> `create_vm()`
  which created a full `EbpfVm` (mock executable, ro_region, stack, heap,
  access violation handler), then extracted the `invoke_context` and
  `memory_mapping` from the VM. The new macro constructs only what the
  allocator tests need. Three differences, all inconsequential:

  1. **Heap backing region is `MAX_HEAP_FRAME_BYTES` (256KB) vs
     `HEAP_LENGTH` (32KB):** The allocator is initialized with
     `HEAP_LENGTH` in both cases, so allocation limits are identical.
     The larger backing region is unreachable address space.
  2. **No access violation handler:** `SyscallAllocFree` only returns
     addresses — it does not read/write through the mapping, so the
     handler is never invoked.
  3. **`aligned_memory_mapping: false` explicitly set:** With a single
     heap region at `MM_HEAP_START`, aligned vs unaligned modes resolve
     identically.
