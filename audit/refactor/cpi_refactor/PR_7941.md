## Summary

Moves the CPI account update functions and their tests from
`syscalls/src/cpi.rs` to `program-runtime/src/cpi.rs`. This is the bulk
of the CPI execution logic — the functions that synchronize account state
between caller and callee before and after cross-program invocation.

## File Summary

All items moved from `syscalls/src/cpi.rs` to `program-runtime/src/cpi.rs`:

### Category B: Structural Changes

- **Visibility:** All moved items changed from private to `pub` for
  cross-crate access.
- **`Error` alias -> `Box<dyn std::error::Error>`:** Return types use
  the explicit form instead of the `type Error` alias from syscalls.
- **`MAX_PERMITTED_DATA_INCREASE` import removed** from
  `syscalls/src/lib.rs` (now only used in program-runtime/src/cpi.rs).

### Category C: Behavioral Changes

**One error variant change in `update_caller_account`:**

```
// Old (syscalls/src/cpi.rs)
.ok_or(SyscallError::InvalidLength)?;

// New (program-runtime/src/cpi.rs)
.ok_or(CpiError::InvalidLength)?;
```

Same error consolidation pattern as #7836 and #7861. The concrete type
inside `Box<dyn Error>` changes but the error message is identical
("InvalidLength") and no production code downcasts these errors. The
`From<CpiError> for SyscallError` impl (added in #7861) maps
`CpiError::InvalidLength` back to `SyscallError::InvalidLength` if
conversion is needed.

**Assessment:** SAFE.
