## Summary

Implements the `sol_get_epoch_stake` syscall per SIMD-0133. Provides
on-chain programs with the ability to query total epoch stake or
per-vote-account stake. Feature-gated behind `enable_get_epoch_stake_syscall`.

## Implementation

### Syscall Registration

```rust
register_feature_gated_function!(
    result,
    enable_get_epoch_stake_syscall,
    *b"sol_get_epoch_stake",
    SyscallGetEpochStake::vm,
)?;
```

Syscall is entirely absent from the runtime environment until the feature
activates. Clean registration pattern using `register_feature_gated_function!`.

### Syscall Logic

Two paths based on `var_addr`:

**Null pointer path (total stake):**
- CU cost: `syscall_base_cost`
- Returns: `invoke_context.get_epoch_total_stake().unwrap_or(0)`

**Non-null path (per-vote-account stake):**
- CU cost: `syscall_base_cost + floor(PUBKEY_BYTES / cpi_bytes_per_unit) + mem_op_base_cost`
- Translates `var_addr` as `Pubkey` via `translate_type` (enforces 32 bytes readable)
- Looks up vote account in `epoch_vote_accounts` hashmap
- Returns stake amount, or 0 if not found

### Data Flow

```
Bank::epoch_total_stake(epoch) ──> TransactionProcessingCallback
Bank::epoch_vote_accounts(epoch) ──> TransactionProcessingCallback
    │
    ▼
TransactionBatchProcessor::execute_loaded_transaction
    │  passes via EnvironmentConfig::new(epoch_total_stake, epoch_vote_accounts, ...)
    ▼
InvokeContext
    │  .get_epoch_total_stake() -> Option<u64>
    │  .get_epoch_vote_accounts() -> Option<&VoteAccountsHashMap>
    ▼
SyscallGetEpochStake::rust
```

### Public API

`sdk/program/src/epoch_stake.rs` provides safe wrappers:
- `get_epoch_total_stake()` — calls syscall with null pointer
- `get_epoch_stake_for_vote_account(vote_address)` — calls syscall with pubkey

## Security Analysis

### 1. Feature Gating

**PASS.** `register_feature_gated_function!` ensures the syscall doesn't
exist in the runtime environment until `enable_get_epoch_stake_syscall`
activates. No way to invoke it before activation.

### 2. Memory Safety

**PASS.** `translate_type::<Pubkey>(memory_mapping, var_addr, check_aligned)`
verifies all 32 bytes at `[var_addr, var_addr+32)` are readable before
dereferencing. VM aborts on access violation — tested.

### 3. Compute Unit Metering

**PASS.** CU formula matches SIMD-0133 spec:
- Null path: `syscall_base` only
- Non-null path: `syscall_base + floor(32/cpi_bytes_per_unit) + mem_op_base`
- Uses `saturating_add` for overflow safety
- `checked_div(...).unwrap_or(u64::MAX)` on `cpi_bytes_per_unit` — if zero,
  guarantees budget exhaustion (safe failure)

### 4. Read-Only Access

**PASS.** The syscall only reads from the `epoch_vote_accounts` hashmap.
It does not modify any account state. Returns a `u64` value. No write
paths, no account mutations, no lamport transfers.

### 5. None Handling

**PASS.** Both `get_epoch_total_stake()` and `get_epoch_vote_accounts()`
return `Option`. When `None` (e.g. warped bank, test bank without epoch
stake data), the syscall returns 0. This is correct — programs should
treat 0 as "data unavailable" and handle accordingly.

### 6. Consensus Safety

**PASS.** Feature-gated. The syscall reads epoch stake which is
deterministic for a given epoch — all validators see the same stake
distribution at the same epoch. No non-deterministic operations.

## Agent Findings Assessment

Agent review (score 82, approved) identified:

1. **Major — `solana-vote` dependency in `svm` and `program-runtime`** —
   Agent correctly flagged this as architectural debt. `VoteAccountsHashMap`
   type from `solana-vote` pulls in `crossbeam-channel` transitively. A
   follow-up should extract this into a trait or micro-crate. **Not a
   security issue, but noted.**

2. **Minor — Untested `None` vote-accounts path** — The else branch
   (returning 0 when `get_epoch_vote_accounts()` is `None`) has no direct
   unit test. Low risk since the behavior is trivially correct (return 0).
   **Agree.**

3. **Minor — `unwrap_or(u64::MAX)` vs `unwrap_or(0)` inconsistency** —
   The CU calculation uses `unwrap_or(u64::MAX)` for zero `cpi_bytes_per_unit`,
   while `sysvar.rs` uses `unwrap_or(0)`. The `u64::MAX` choice causes
   guaranteed budget exhaustion (safe failure). Different from `unwrap_or(0)`
   which would make it free. **Not a security issue — the safe choice was
   made.**

## Test Coverage

- `test_syscall_get_epoch_stake_total_stake` — null pointer returns total
  stake, CU budget set to exact expected value
- `test_syscall_get_epoch_stake_vote_account_stake` — three sub-tests:
  1. Access violation on partial memory region (31 bytes instead of 32)
  2. Valid vote address returns correct stake
  3. Unknown vote address returns 0
- CU budgets in tests are set to exact expected values — any over-charging
  would cause test failure

## Verdict

**PASS** — Clean syscall implementation. Feature-gated registration,
correct CU metering per SIMD-0133, memory-safe Pubkey translation,
read-only access pattern. The `solana-vote` dependency is architectural
debt but not a security concern. Well-tested core paths.
